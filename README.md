# wifi-watchdog

Сторож Wi-Fi для домашнего роутера. Домашний сервер, подключённый к роутеру **кабелем**, своим Wi-Fi-адаптером
проверяет, пускает ли роутер в сеть, и при сбое сам перезапускает вещание Wi-Fi, а если не помогло — перезагружает роутер.

Сделан под конкретную неприятность: старый TP-Link раз в несколько дней перестаёт подключать устройства.
Сеть видна, пароль верный, подключение крутится и не проходит; после перезагрузки роутера всё снова работает.
По кабелю такой сбой не заметен — интернет на сервере продолжает работать, — поэтому проверка идёт настоящим
подключением по Wi-Fi.

## Как работает

1. Раз в 3 минуты сервер подключается к домашней сети своим Wi-Fi-адаптером, получает адрес по DHCP и сразу отключается.
   Профиль подключения не становится маршрутом по умолчанию и не меняет DNS: весь трафик сервера остаётся на кабеле.
2. Три неудачи подряд — сервер по кабелю заходит в веб-интерфейс роутера и выключает-включает вещание 2,4 и 5 ГГц.
3. Через 2,5 минуты Wi-Fi всё ещё не работает — полная перезагрузка роутера и пауза 15 минут.
4. Не больше 3 перезагрузок в сутки. Если предел исчерпан, а Wi-Fi не ожил, служба завершается с ошибкой
   (`systemctl --failed`), чтобы это заметил мониторинг.

Когда ничего не перезагружается:

- роутер не отвечает серверу по кабелю (команду всё равно не отправить);
- Wi-Fi-адаптер сервера не видит вообще ни одной сети (сломан адаптер, а не роутер).

## Что нужно

- Linux с systemd и NetworkManager (проверено на Ubuntu 26.04).
- Сервер подключён к роутеру кабелем, и у него есть свободный Wi-Fi-адаптер.
- Python 3 и `uv` либо пакет `python3-venv`.
- Роутер **TP-Link Archer C5 v4** (проверено на прошивке `3.23.11 0.9.1 v6020.0 Build 200408`).

С другими роутерами проба Wi-Fi работает как есть, а вот команды перезагрузки — нет: их отправляет `router.py`
через библиотеку [tplinkrouterc6u](https://github.com/AlexandrErohin/TP-Link-Archer-C6U). Для другой модели TP-Link
замените в `router.py` класс клиента на подходящий из этой библиотеки. Для роутера другой марки подставьте свою
программу с действиями `check`, `wifi-restart`, `reboot` через переменную `WIFI_WATCHDOG_ROUTER_CMD`.

## Установка

```bash
git clone https://github.com/intstage/wifi-watchdog.git
cd wifi-watchdog
sudo ./install.sh
sudoedit /etc/wifi-watchdog/config        # IFACE — имя Wi-Fi-адаптера (ip -br link), ROUTER_IP — адрес роутера
sudo wifi-watchdog-setup                  # спросит имя сети, пароль Wi-Fi и пароль администратора роутера
sudo systemctl enable --now wifi-watchdog.timer
```

`wifi-watchdog-setup` сразу проверяет оба пароля: пробует подключиться к Wi-Fi и войти в роутер.
Пароль Wi-Fi хранится в профиле NetworkManager в виде ключа (PBKDF2), а не открытым текстом;
пароль администратора — в `/etc/wifi-watchdog/router-password` (root, 600).
Сменили любой из паролей — запустите `wifi-watchdog-setup` ещё раз, иначе сторож примет это за сбой.

## Команды

| Команда | Что делает |
|---|---|
| `sudo wifi-watchdog --status` | счётчики: неудач подряд, перезагрузок за сутки, пауза |
| `sudo wifi-watchdog --probe` | одно пробное подключение, без счётчиков и действий |
| `sudo wifi-watchdog --wifi-restart-now` | вручную перезапустить вещание Wi-Fi (сеть пропадёт примерно на минуту) |
| `sudo wifi-watchdog --reboot-now` | вручную перезагрузить роутер |
| `journalctl -t wifi-watchdog` | журнал сторожа |
| `sudo /usr/local/lib/wifi-watchdog/router.py check` | войти в роутер и показать прошивку и число клиентов |

Ручные команды запускают действие отдельной задачей systemd и сразу отвечают `ok`: их можно вызывать по SSH
с ноутбука, который сам сидит на этом Wi-Fi, — обрыв связи команду не прервёт.

Проверить логику без настоящего сбоя и без роутера:

```bash
sudo env WIFI_WATCHDOG_STATE_DIR=/tmp/ww-test WIFI_WATCHDOG_FAKE_PROBE=fail \
     WIFI_WATCHDOG_ROUTER_CMD=/bin/true wifi-watchdog
```

Три запуска подряд дойдут до «перезапуска вещания», четвёртый — до «перезагрузки» (между запусками сбрасывайте
паузу: `echo 0 | sudo tee /tmp/ww-test/backoff_until`).

## Замеры на Archer C5 v4

- Пробное подключение: около 7 секунд на проход, из них само подключение — около секунды.
- Перезапуск вещания 2,4 и 5 ГГц: около 70 секунд, кабельные клиенты не затронуты.
- Перезагрузка: роутер снова отвечает через ~60 секунд, Wi-Fi принимает подключения через ~90.

## Ограничения

- Проверяется одна сеть (один SSID) — та, к которой подключается адаптер сервера.
- Вход скрипта в веб-интерфейс выкидывает из него администратора: у роутера одна сессия.
- Причину сбоя сторож не устраняет и журнал роутера перед перезагрузкой не сохраняет.
- Команды роутеру идут по HTTP внутри домашней сети — так устроен сам веб-интерфейс этой модели.

## Удаление

```bash
sudo systemctl disable --now wifi-watchdog.timer
sudo rm -f /etc/systemd/system/wifi-watchdog.{service,timer} /usr/local/sbin/wifi-watchdog /usr/local/sbin/wifi-watchdog-setup
sudo rm -rf /usr/local/lib/wifi-watchdog /opt/wifi-watchdog /etc/wifi-watchdog /var/lib/wifi-watchdog
sudo nmcli con delete wifi-probe
sudo systemctl daemon-reload
```
